## GGUF tensor loading details:
- GGUF stores shapes as [ne0, ne1] where ne0 is the inner/fast dimension
- We reverse to [rows, cols] = [ne1, ne0] when loading
- For a weight matrix W that maps input[K] → output[N]:
  - GGUF stores it as shape [K, N] (ne0=K, ne1=N)
  - We reverse to [N, K] for our shape tracking
  - In memory, element W[n][k] is at flat index n*K + k (row-major)
  - Our matvec shader computes: output[n] = sum_k(W[n*K + k] * input[k])
  - This matches GGUF layout WITHOUT any transpose

## Key question about weight dimensions:
- For ffn_gate.weight: GGUF shape [ne0=1536, ne1=8960] → we store as [8960, 1536]
  - Matvec: output[n] = sum_k(W[n*1536 + k] * input[k]), n=0..8959, k=0..1535
  - This maps hidden_dim(1536) input → intermediate_dim(8960) output ✓
- For ffn_down.weight: GGUF shape [ne0=8960, ne1=1536] → we store as [1536, 8960]
  - Matvec: output[n] = sum_k(W[n*8960 + k] * input[k]), n=0..1535, k=0..8959
  - This maps intermediate_dim(8960) input → hidden_dim(1536) output ✓

### matvec.wgsl:
```wgsl
@compute @workgroup_size(256, 1, 1)
fn main(@builtin(global_invocation_id) gid: vec3<u32>) {
    let n = gid.x;
    if (n >= params.N) { return; }
    var sum: f32 = 0.0;
    let w_base = n * params.K;
    // output[n] = sum_k(W[n*K + k] * input[k])
    for k in 0..K { sum += weights[w_base + k] * input[k]; }
    output[n] = sum;
}
```
